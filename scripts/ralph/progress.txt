# Ralph Progress Log

## Codebase Patterns
- Use `createRouteWithStops` mutation for atomic route creation (routes.ts:332-482)
- Map components are in `packages/maps/src/components/` - use InteractiveMap for admin
- Student coordinates are in `homeLatitude` and `homeLongitude` fields
- Route type is "pickup" | "dropoff" in schema
- Use existing RouteOptimizer pattern for Google Directions API calls
- Spanish language for all UI text (Ecuador/Colombia localization)
- Brand colors: primary #042940, accent #DBF227

- PageHeader component supports multiple action buttons with variant styling
- WizardStepIndicator can be reused for multi-step wizards (responsive, mobile-friendly)
- Step content placeholders allow incremental wizard development

- FleetSummary component shows loading skeletons, then summary cards for vehicles/drivers/monitors/students
- Use getBulkWizardFleetSummary Convex query for onboarding stats (routes.ts:895-1001)
- Step2StudentSelection uses GoogleMapsProvider and InteractiveMap from @altaviapp/maps
- Split view layout: lg:w-1/2 for 50/50 on large screens, stacks on mobile
- getStudentFilterOptions query (routes.ts:1173-1242) returns grades and parentNames for filter dropdowns
- Use custom useDebounce hook for search input filtering (300ms delay)
- StudentFilters interface: { search?, grade?, parentName?, hasGps? }
- Filter bar includes: search input, grade dropdown, parent dropdown, GPS toggle, reset button
- Core UI components: Input, Select, Switch from @/components/core

- InteractiveMap supports showInfoWindow={true} prop for click-to-show marker popups
- getStudentsMapData query fetches only selected students' coordinates for map visualization
- Use google.maps.LatLngBounds() + mapRef.fitBounds() for auto-zoom to markers
- Route clustering service: use clusterStudentsForRoutes from apps/admin/src/services/routeClustering.ts
- calculateHaversineDistance available from @altaviapp/maps for geographic distance calculations
- K-means++ initialization provides better cluster spread (furthest point from school first)
- Step4RouteReview uses 1/3 + 2/3 split layout (lg:w-1/3, lg:w-2/3) for route cards + map
- RouteCard sub-component pattern for reusable route display elements
- Format duration: < 60 min shows as "X min", >= 60 shows as "Xh Ymin"
- Format distance: < 1000m shows as meters, >= 1000m shows as km with 1 decimal
- Route optimization service: use optimizeRouteOrder from apps/admin/src/services/routeOptimization.ts
- Google Directions API: wrap callback in Promise for async/await, use region: "EC" for Ecuador
- Calculation flow pattern: validate -> cluster students -> optimize each cluster -> collect results
